# CLAUDE.md

Guidance for Claude Code sessions on this repo. Read before making changes.

## What this project is

Two related static sites, both served by GitHub Pages from `docs/`:

1. **Most Played Games of All Time** (`docs/index.html`) — a yearly ranking of
   BGG's most-played board games since January 2010, based on monthly play
   counts. Published as an interactive site *and* as a BGG geeklist. Latest
   published edition: 2026.
2. **My Personal Collection** (`docs/collection/`) — the owner's own board
   games, browsable with the same filters as the main page but a different
   sort menu (rating-based, no rank/delta sorts). Rebuilt from
   `collection.csv` (exported from BGG) whenever the owner updates it.

Both are backed by a Python pipeline that scrapes BGG (Selenium), builds JSON
payloads, and archives each edition.

## Yearly edition workflow (most-played)

Not run automatically — the owner walks through it every May, using PyCharm.

1. Edit `config.py`: set `END_YEAR` (confirm `END_MONTH = 5`).
2. Run `main.py`. Scrapes (resumable), computes scores, builds games.json,
   builds docs/web_data.json + credits_data.json, produces geeklist.txt.
3. Review scores.json / games.json / geeklist.txt at the project root.
4. Publish the geeklist manually on BGG (BBCode paste, one item at a time).
5. Update `docs/current_geeklist.json` with the new geeklist URL/id.
6. Commit & push. GitHub Pages picks up docs/* automatically.
7. Run `archive_edition.py` to freeze the edition:
   - Writes `archive/<YEAR>.json` (source of truth for next year's deltas).
   - Creates `YYYY_MM_DD_Published_version_April_YYYY/`.
   - MOVES scores.json, games.json, geeklist.txt into it.
8. Commit the new archive file and the published-version folder.

## Collection workflow

Independent from the yearly pipeline. Whenever the owner updates their BGG
collection:

1. Export from BGG as CSV, save as `collection.csv` at the project root.
2. Run `maintain_my_collection_extra_info.py`. Fill new entries in
   `my_collection_extra_info.json` (French titles override English ones on
   the collection page; the `age` field is your own estimated minimum age,
   left `null` until you set it by hand).
3. Run `build_collection.py`. It scrapes any missing metadata, then writes
   `docs/collection/collection_data.json`.
4. Commit & push.

If `scrape_metadata.py` changes and needs to re-scrape expansions, use
`clear_expansion_cache.py` to purge only expansion caches (asks for
confirmation).

## Conventions (follow these)

### Python

- **Prefer module-level global constants over CLI args.** Scripts are run
  via PyCharm's green Run button, not from the shell. Constants live at
  the top of each script or in `config.py`.
- **`config.SELENIUM_HEADLESS` and `config.CACHE_METADATA_DIR`** are the
  authoritative names. Don't hard-code `headless=False` or `CACHE_DIR_GAME_METADATA`.
- **After `scrape_game()`, always call `scrape_metadata.save_metadata_cache()`.**
  `scrape_game()` returns the dict but does NOT persist it.
- **JSON everywhere.** No CSVs in the pipeline (except `collection.csv` as
  input). Two-cache split: `cache/game_metadata/` and `cache/monthly_rankings/`.
- **The main entry point of a script is a function** (e.g. `build_scores()`,
  `check_coverage()`), with a `if __name__ == "__main__": <fn>()` at the
  bottom. `prepare_geeklist.py` uses `main()` for that entry point.
- **`archive/<YEAR>.json` is a source of truth.** Never regenerate it after
  publication; next year's deltas depend on it. `archive_edition.py` guards
  against overwrites via `OVERWRITE=False`.
- **Extensions are excluded** from the most-played rankings via
  `scrape_rankings.py`'s `/boardgame/` URL filter. Only base games count.
- **`EXCLUDED_BGG_IDS = {18291}`** ("Unpublished Prototype"). Do not extend
  this set to filter "reeditions" or "special editions" — the editorial
  policy is "if BGG says boardgame, we take it", even for
  Castles of Burgundy 84876 / 271320 / 363622 or Ticket to Ride /
  Ticket to Ride Europe.

### Frontend

- **`[hidden] { display: none !important; }`** is a global rule in
  `docs/style.css`. Essential because we set `display: flex` on
  `.filters-body` and other elements; without it, the HTML `hidden`
  attribute would be overridden.
- **`.gitignore` root-only patterns need `/` prefixes.** `/games.json`
  ignores at root only; `games.json` (no slash) would ignore in every
  subdirectory — the archive folders would be affected too.
- **Vanilla HTML/CSS/JS**, no build step, no framework. Fonts: EB Garamond
  from Google Fonts, non-blocking load via `media="print" onload="..."`.
- **Cream / ink palette on the main site** (`--bg: #faf8f3`, `--ink: #1a1a1a`,
  `--accent-up: #3d7a3f` green). Collection page overrides `--accent-up`
  to terracotta `#b86a3e` and adds a 1.5px border on cards & filters
  panel for identity.
- **The card image backdrop uses `padding: 5px` on `.card-image-link` and
  `inset: -80px; filter: blur(32px) brightness(1.5) saturate(0.85); opacity: 1.0`
  on the `::before`.** These values are the result of iteration; don't
  change them without a good reason.
- **`Intl.Collator("fr", {sensitivity: "base", numeric: true})`** is used
  for title sort on the collection page so "Échecs" sorts among the E's,
  not after Z.
- **Both pages default the Players selector to "community"**, via
  `<option value="community" selected>` in HTML. Same for the Age selector
  on the main page. On the collection page, Age defaults to "my opinion"
  (`age-source` value `"mine"`) instead, since that page has a personal
  age estimate (`age.mine` in `collection_data.json`, sourced from
  `my_collection_extra_info.json`) that falls back to the community age
  when unset.

### Style / language

- **Avoid em-dashes (`—`) in generated text.** The owner is French-speaking
  and reads them as an "LLM tell". Use periods, commas, or parentheses
  instead.
- **The owner sometimes writes in French.** Respond in French when they do.
- **Prefer sober, minimal design** over decorative choices. When adding UI,
  err toward less rather than more.
- **Prefer pragmatism over elegance** when the trade-off is real. E.g.
  the geeklist is published by manual copy-paste, not by scripting BGG's
  UI, because the yearly effort is acceptable and the automation risk isn't.

## Don't do

- Don't regenerate `archive/<YEAR>.json` for an already-published edition
  (breaks year-over-year deltas). `OVERWRITE=False` in `archive_edition.py`
  guards this.
- Don't rename generated file paths without updating the whole pipeline
  AND the frontend's `fetch(...)` URLs.
- Don't add a "Collection" link to the main site's nav — the collection
  is intentionally accessible only via the discreet footer link, not
  promoted in the top nav (see the shared `nav.js`).
- Don't ship images downloaded from BGG. The frontend links to
  `cf.geekdo-images.com` directly; no local mirror.
- Don't hard-code URLs like `https://github.com/` as placeholders — the
  real URL is `https://github.com/francois-durand/bgg_most_played_games`.

## Useful entry points for common tasks

- Change the top-N cutoff: `TOP_N` in `build_web_data.py` (250 currently).
- Change the point formula: `point_function()` in `build_scores.py`
  (currently `rank^(-0.5)`).
- Change the intro text on the main site: `<p class="site-intro">` in
  `docs/index.html`.
- Change the methodology page: `docs/about.html`.
- Change the geeklist item format: `_format_item()` in `prepare_geeklist.py`.
- Add a coverage check on a new field: `FIELDS` list in `check_coverage.py`.
